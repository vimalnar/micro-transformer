# Training and inference workflow

The training package builds causal next-token models from prepared episodes. The
model is trained from random initialization unless a run explicitly supplies a
checkpoint or enables LoRA. Ordinary inference uses fixed weights.

## Data flow

```text
fixed language + seeded generator
          ↓ JSONL and provenance manifest
prepare_data validation and packed arrays
          ↓ prepared split
train.py → run directory (config, architecture snapshot, logs, checkpoints)
          ↓ selected checkpoint
evaluate.py / infer.py → predictions and metrics
```

The generator and interpreter do not require PyTorch. Preparation validates
records and encodes tokens. Training reads packed data, batches independent
right-padded episodes, and masks padding targets. The standard objective is
next-token cross-entropy. Expected answers and task labels are not additional
model input features. Create the training environment using the
[setup guide](setup.md), including its editable package-install step, before
running the commands below.

## Generate and prepare a small dataset

The generation count is episodes, not tokens. Use a small local corpus to learn
the interface; it is not a substitute for the fixed release data in a direct
reproduction.

```bash
.venv/bin/python scripts/generate_dataset.py \
  --episodes 1000 --split train --seed 46090 \
  --output artifacts/datasets/tutorial-train.jsonl \
  --require-full-coverage

.venv/bin/python scripts/generate_dataset.py \
  --episodes 200 --split validation --seed 46091 \
  --output artifacts/datasets/tutorial-validation.jsonl \
  --require-full-coverage

.venv-training/bin/python -m training.prepare_data \
  --input artifacts/datasets/tutorial-train.jsonl \
  --output artifacts/datasets/prepared/tutorial-train

.venv-training/bin/python -m training.prepare_data \
  --input artifacts/datasets/tutorial-validation.jsonl \
  --output artifacts/datasets/prepared/tutorial-validation
```

Use a different seed and split for validation. Preserve each JSONL file and its
manifest if the generated bytes are part of an experiment identity. The generator
protects existing outputs; use new paths for new runs.

## Train a small model

```bash
.venv-training/bin/python -m training.train \
  --architecture models/transformer.py \
  --model-config training/configs/baseline.json \
  --train-data artifacts/datasets/prepared/tutorial-train \
  --validation-data artifacts/datasets/prepared/tutorial-validation \
  --run-dir artifacts/runs/tutorial-01 \
  --steps 100 --batch-size 32 --seed 42 --device cpu
```

This is an interface demonstration, not a scientifically powered model result.
Run commands from the repository root. Training supports explicit architecture,
model configuration, data paths, step count, batch size, seed and device. Check
`python -m training.train --help` for the options available in the checked-out
revision.

The full reference protocol is documented in
[training README](https://github.com/vimalnar/micro-transformer/blob/main/training/README.md) and the
[experiment guide](experiment-guide.md). It uses named data identities, multiple
seeds, validation-based checkpoint selection and fixed final evaluation suites.

## Objective and checkpoint selection

The default objective predicts each next token. Independent episodes are batched
with right padding; padding targets are excluded from loss. Optional answer
weighting changes the training loss weighting but does not add information to the
inference prompt. Optional checkpoint selection metrics use validation only; the
held-out test suite must not select the checkpoint.

Training configurations are starting points and historical protocol values, not
claims of optimality. For causal architecture comparisons, hold the declared data,
initialization seeds, optimizer, update budget, checkpoint rule and test suites
constant. Run baseline and candidate from fresh initialization. LoRA begins from
the frozen reference and answers a different question (adaptation).

## Inference and evaluation

Use the bundled baseline with:

```bash
.venv-training/bin/python -m training.infer \
  --checkpoint baselines/v1.0.0/checkpoints/seed42-inference.pt \
  --prompt 'hal move flag six to river. hal tell gia flag six at river. where gia knows flag six?'
```

Use `training.evaluate` for a declared evaluation split and retain raw predictions
alongside aggregate metrics. The exact options depend on the selected data and
checkpoint; consult `python -m training.evaluate --help` and the training README.
The lightweight `harness/talk_to_micro_transformer.py` is for interactive use and
is not a substitute for a full evaluation report.

## Run artifacts and reproduction

Each research run should preserve its configuration, architecture source snapshot
and hash, dataset manifests/hashes, seed, runtime/device information, checkpoint,
metrics, predictions where applicable, and any replay or evaluation identities.
Keep development/validation exposure distinct from protected final evaluation.

The small bundled checkpoint omits optimizer and random-state data, so it supports
inference and a new adaptation run, not exact continuation of its original training
trajectory. The larger preliminary model currently has no public downloadable
checkpoint. See the [model specifications](../specifications/model-specifications.md)
and [reproducibility guide](reproducibility.md).
